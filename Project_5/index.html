Overall Quality and Parameter Comparison

When creating the embeddings, you will see tensors like this: tensor([[[-0.0322, -0.0893, 0.0569, ..., 0.0608, -0.0345, 0.0080], [ 0.0350, 0.0930, -0.0676, ..., 0.1038, -0.1740, -0.0928], [-0.0583, 0.1975, 0.0878, ..., 0.1200, -0.0617, -0.0642], ..., [ 0.0479, 0.1035, 0.0232, ..., 0.1868, -0.1043, -0.1133], [ 0.0479, 0.1035, 0.0232, ..., 0.1868, -0.1043, -0.1133], [ 0.0479, 0.1035, 0.0232, ..., 0.1868, -0.1043, -0.1133]]], dtype=torch.float16). Below you can see 3 images produced for 3 different prompts for different number of inference steps and different resolutions. You can see that the more inference steps, the better the image quality. The resolution may seem to have an impact on quality, but this is because of upscaling for presentation purposes. You can see how a larger number of inference steps allows for more detail and arguably a better image. For example, the wine glass has much more texture and the scene has more detail. Likewise, for the bird and mountain, they add more lines and "information" as the steps increase.

1.7.2 Inpainting

What we can also do is mask certain parts of the image to modify the image. By placing a mask and iteratively generating a new section for both inside and outside the mask, the stitching the two together, we can iteratively move the model to editing parts of the image while leaving other parts untouched.

1.8 Visual Anagrams

We can also make visual anagrams that look like one image one way and another image when flipped. This is done by denoising the image in two directions, then adding the flipped versions together. This slowly moves the image to a "middle ground" which beautifully ends up being an anagram.

The result are very blurry images that seems to resemble a mixture of numbers. This makes sense. Because the model is given noise and tries to predict numbers, to optimize over many images, it is best to create a "generic" number that is somewhat close to all the numbers. Hence you get the hybrid image.
